# 0014. 상품 카테고리와 상태를 enum으로 관리

## 상태
확정

## 배경
ERD에서 Product의 category와 status는 문자열 컬럼으로 정의되어 있으나,
자바 코드에서 이 값을 어떤 타입으로 다룰지는 정해지지 않았음. MVP의
카테고리 필터링이 일관되게 동작하려면 허용 값의 범위를 정할 필요가 있음.

## 고민한 선택지
1. String: 자유 문자열로 저장하고 필요 시 별도 검증
2. enum + EnumType.STRING: 고정된 상수 목록으로 표현하고 이름을 저장
3. Category 테이블(엔티티): 카테고리를 별도 테이블로 두고 FK로 참조

## 결정
카테고리와 상태 모두 2번 채택.
- ProductCategory: DIGITAL(디지털/가전), FURNITURE(가구/인테리어),
  CLOTHING(의류/패션잡화), BOOK(도서), LIVING(생활/주방),
  SPORTS(스포츠/레저), ETC(기타)
- ProductStatus: ON_SALE(판매중), RESERVED(예약중), SOLD(판매완료)
- 화면 표시용 한국어 이름은 enum의 별도 필드로 둠
- DB 컬럼은 @JdbcTypeCode(SqlTypes.VARCHAR)로 VARCHAR를 명시함

## 이유
### 카테고리
- 현재 카테고리는 서비스가 정하는 작고 평면적인 고정 목록이며, 노출 순서,
  계층 구조, 사용 중지 같은 카테고리 자체의 데이터가 없음. 이 경우 enum으로
  허용 값을 표현하는 것이 별도 검증 로직이나 조회 구조를 두는 것보다 단순함.
- String은 검증을 별도로 구현해야 같은 효과를 얻을 수 있고, Category
  테이블은 현재 요구사항에서 활용할 데이터가 없어 구조만 늘어남.
- 어떤 분류에도 맞지 않는 상품도 등록할 수 있도록 ETC를 둠.

### 상태
- 상태는 분류 데이터가 아니라 상태 전이 규칙을 가진 값이므로, 허용 값을
  타입으로 제한하는 것이 자연스러움.
- 단, enum은 허용된 값만 제한할 뿐 전이 순서(판매완료 → 예약중 금지 등)나
  동시 변경을 막지 않음. 전이 규칙은 엔티티의 도메인 메서드에서, 동시성은
  Transaction 단계의 락으로 다룸.

### EnumType.STRING과 VARCHAR 명시
- EnumType.ORDINAL은 순서 번호를 저장하므로, 상수 순서가 바뀌면 기존 데이터가
  다른 상수로 해석됨.
- Hibernate 6.2 이후 MySQL에서 EnumType.STRING은 기본적으로 네이티브 ENUM
  타입으로 매핑됨. 이 경우 상수를 추가해도 ddl-auto=update는 기존 컬럼 정의를
  변경하지 않아, 새 값 저장 시 오류가 발생함. VARCHAR를 명시해 상수 추가 시
  스키마 변경이 필요 없도록 하고, ERD의 문자열 컬럼 정의와도 일치시킴.

## 트레이드오프
- 카테고리를 추가하려면 코드 수정과 재배포가 필요함. 카테고리는 자주 바뀌는
  값이 아니므로 감수함.
- VARCHAR로 저장하면 DB 수준에서 허용 값을 제한하지 않음. 값 검증은
  애플리케이션(enum 바인딩)이 담당함.
- enum 상수명은 DB 저장 값이자 API 요청 값이므로 단순 리팩터링으로 변경할
  수 없음. 이름 변경이나 삭제 시 기존 데이터 마이그레이션이 필요함.
- 노출 순서, 계층 구조, 사용 중지 등 카테고리 자체의 데이터가 필요해지면
  Category 테이블로의 전환을 재검토함.

## 입력 처리 규칙
- 등록/수정 요청의 카테고리가 누락되면 400, 알 수 없는 값이면 400
- 목록 조회에서 카테고리 파라미터를 생략하면 전체 조회, 알 수 없는 값이면 400
- 알 수 없는 값을 ETC로 대체하지 않음. 사용자의 "기타" 선택과 잘못된 입력을
  구분하기 위함.

## 기존 코드 반영
- 이 결정 과정에서 실제 DDL을 확인한 결과, 기존 Member.role 컬럼이
  EnumType.STRING 매핑에 의해 MySQL 네이티브 ENUM('USER')으로 생성되어
  있었음. 역할 상수를 추가하면 같은 문제가 발생하므로 동일한 방식으로 수정함.
- 엔티티에 @JdbcTypeCode(SqlTypes.VARCHAR)와 length = 20을 명시하고,
  ddl-auto=update는 기존 컬럼 타입을 변경하지 않으므로 로컬 DB는
  ALTER TABLE member MODIFY role VARCHAR(20) NOT NULL로 직접 변경함.
- 이후 enum 필드는 모두 같은 방식(EnumType.STRING + VARCHAR 명시)으로 매핑함.
