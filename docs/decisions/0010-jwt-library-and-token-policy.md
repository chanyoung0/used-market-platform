# 0010. JWT 구성: Nimbus JOSE + JWT 사용, Access Token 만료 1시간, 시크릿 키는 .env로 관리

## 상태
확정

## 배경
ADR 0004에서 Access Token 단일 발급 방식을 정했고, 이를 구현하려면 토큰 서명/검증을 수행할 라이브러리, 만료 시간, 서명용 시크릿 키 관리 방식이 필요했음. 이 프로젝트는 Spring Boot 4.1.1을 사용하며 기본 JSON 라이브러리가 Jackson 3(tools.jackson)이라, JWT 라이브러리가 내부에서 쓰는 Jackson 버전과의 호환성이 선택 기준이 됨.

## 고민한 선택지
라이브러리
1. jjwt + Jackson 2 호환 모듈 추가
2. jjwt + Gson 모듈 (jjwt-gson)
3. Nimbus JOSE + JWT
4. auth0 java-jwt

만료 시간
1. 1시간 단일 고정
2. 30분 + 활동 시 갱신

## 결정
- 라이브러리: Nimbus JOSE + JWT 채택. 토큰 생성/검증만 라이브러리에 맡기고, 토큰 제공자(JwtTokenProvider)와 인증 필터(JwtAuthenticationFilter)는 직접 구현함. Spring Security의 resource server 자동 구성은 사용하지 않음.
- 만료 시간: Access Token 1시간, 갱신 없음.
- 시크릿 키: .env에 32바이트(256비트) 이상 문자열로 두고 설정 값으로 주입함. 코드에는 포함하지 않음.

## 이유
- jjwt는 JSON 처리를 Jackson 2 모듈에 의존하며, Jackson 3 지원은 메인테이너가 JDK 17 기준 문제로 일정이 없다고 밝힌 상태임. 사용하려면 폐기 예정인 Jackson 2를 추가하거나(1번), JSON 라이브러리를 하나 더 얹어야 함(2번). 1번은 ADR 0001에서 세운 "유지보수가 끊겼거나 폐기 예정인 의존성을 처음부터 넣지 않는다"는 기준과 맞지 않음.
- auth0 java-jwt는 최신 릴리스가 아직 Jackson 2 기반이며, Jackson 3 전환은 5.0.0 계획 단계임.
- Nimbus는 JSON 처리에 Gson을 내부에 포함(shaded)해서 쓰므로 프로젝트의 Jackson 버전과 충돌하지 않음. Spring Security가 JWT 처리에 내부적으로 사용하는 라이브러리라 생태계와 맞음.
- 필터와 토큰 제공자를 직접 구현하는 이유는 인증 흐름(토큰 추출, 검증, SecurityContext 설정)을 직접 다루기 위함이며, 자동 구성을 쓰면 이 과정이 감춰짐.
- 만료 1시간은 ADR 0004의 "1시간 이내" 범위 안에서 가장 단순한 값임. 활동 시 갱신 방식은 필터 로직과 응답 처리가 늘고 Refresh Token이 풀려는 문제와 겹치므로 ADR 0004를 다시 다룰 때 함께 결정함.
- 시크릿 키가 유출되면 임의 회원의 토큰을 위조할 수 있으므로 코드와 저장소에 포함하지 않음. HS256 서명에는 최소 256비트 키가 필요함.

## 트레이드오프
- jjwt에 비해 한국어 레퍼런스와 예제가 적어 공식 문서를 기준으로 구현해야 함.
- 만료 1시간 고정이라 탈취된 토큰은 만료 전까지 유효함(ADR 0004의 트레이드오프와 동일). 이후 30분 + 갱신 방식으로 바꿀 경우 ADR 0004를 갱신하는 별도 결정으로 다룸.
- .env는 로컬 개발용 관리 방식이며, 배포(EC2) 시점에는 서버 환경 변수 주입 등으로 시크릿 관리 방식을 재검토함.
- 키 로테이션(키 교체) 방식은 정하지 않음. 키를 바꾸면 기존 토큰이 전부 무효가 됨.
- Spring Boot가 Nimbus 버전을 관리하지 않아 build.gradle에 버전(10.9.1)을 직접 명시함. 보안 패치 반영을 위해 버전을 주기적으로 확인해야 함.
