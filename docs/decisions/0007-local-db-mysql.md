# 0007. 로컬 개발 DB: H2 대신 MySQL(Docker) 사용

## 상태
확정

## 배경
DB 연결 설정 없이 서버를 띄웠더니, Spring Boot가 클래스패스의 H2를 감지해서 인메모리 DB를 자동으로 연결하고 있었음. 의도한 선택이 아니었기 때문에, 로컬 개발 환경의 DB를 명시적으로 정할 필요가 생김. README의 기술 스택은 MySQL(운영), H2(테스트)로 정해져 있어서 로컬 개발 DB만 빈칸이었음.

## 고민한 선택지
1. 로컬 개발도 H2 인메모리 사용
2. 로컬 개발은 MySQL(Docker 컨테이너), H2는 테스트 전용

## 결정
2번 채택.

## 이유
- 운영과 같은 DB 엔진으로 개발하면 SQL 방언, 타입 처리 차이로 배포 후에야 드러나는 문제를 개발 단계에서 미리 발견할 수 있음.
- 0002에서 예고한 비관적 락 기반 동시성 처리는 DB 엔진마다 락 동작이 달라서, H2에서 통과한 결과를 신뢰하기 어려움. 실제 운영 엔진에서 검증해야 트러블슈팅 사례로서 의미가 있음.
- 서버를 재시작해도 데이터가 유지되어, 매번 회원가입부터 다시 하지 않아도 됨.
- 기술 스택에 포함한 Docker를 개발 환경 구성에 실제로 활용하게 됨.

## 트레이드오프
- 개발을 시작하기 전에 MySQL 컨테이너를 먼저 띄워야 하는 번거로움과 초기 설정 비용이 생김.
- dev/prod 프로필 분리는 보류함. 아직 배포 환경(EC2)이 없어 운영 설정이 무엇이 다른지 알 수 없기 때문이며, EC2 배포 시점에 다시 다룸.
- 일반 기능 테스트는 H2로 충분하지만, 동시성 테스트는 H2 결과를 신뢰하기 어려워 MySQL로 돌려야 할 수 있음. Transaction 도메인 구현 시점에 다시 결정함.
