# 0004. JWT 토큰 전략: Access Token 단일 발급 (Refresh Token 미도입)

## 상태
확정

## 배경
JWT는 서버가 상태를 들고 있지 않는(stateless) 방식이라, "로그아웃"이라는
개념이 세션 기반 인증과 다르게 애매함. 이를 어떻게 처리할지 결정이 필요했음.

## 고민한 선택지
1. Access Token만 발급. 로그아웃은 클라이언트가 토큰을 삭제하는 것으로 처리
   (서버는 아무 상태도 관리하지 않음)
2. Access Token(단수명) + Refresh Token(장수명) 발급, Refresh Token을
   서버 DB에 저장해 로그아웃 시 해당 토큰을 무효화

## 결정
1번 채택.

## 이유
- 2번은 Refresh Token 저장/재발급/무효화 로직까지 구현 범위가 늘어나,
  MVP 단계에서 감당하기엔 학습 목표(핵심 도메인 로직) 대비 과함.
- Access Token 만료 시간을 짧게(예: 1시간 이내) 설정해, 로그아웃 후에도
  토큰이 유효한 위험 구간을 최소화하는 방식으로 완화.

## 트레이드오프
- 로그아웃을 눌러도 Access Token 자체는 만료 전까지 여전히 유효함
  (탈취당했을 경우 즉시 무효화 불가). 실제 서비스라면 치명적일 수 있는
  약점이지만, 포트폴리오 MVP 범위에선 감수하기로 함.
- 이후 Refresh Token 도입이 필요해지면 별도 결정 기록으로 다룰 예정.
